# Autonomous AI-SWE & Observability Platform (v2 — Production-Grade)

An enterprise-grade, open-source autonomous software engineering platform. The agent ingests
software issue tickets, parses repository context, plans a fix, writes code patches (single-
or multi-file), runs unit + regression tests in an isolated sandbox, has its diff reviewed by
a critic agent, iteratively self-corrects based on test failure traces, optionally waits for
human approval, and creates a clean Git commit — all benchmarked against an industry-standard
test set and fully traced end-to-end.

---

> **Free-tier note (2026):** Google pulled Gemini Pro models down to near-zero free quota in
> late 2025/2026 — this project uses **Gemini 2.5 Flash only** for planning/ingestion, which

## 1. Project Overview & Architecture Philosophy

* **The Inspiration:** A modular, transparent, open-source alternative to tools like
  **Claude Code**, **Open-SWE**, **SWE-agent**, and **OpenHands**.
* **Core Philosophy:** Rather than training base model weights from scratch, this project
  engineers the **autonomous cognitive architecture, safety rails, execution sandboxes,
  verification layers, and observability stack** around pre-trained model APIs
  (Google Gemini Flash & Groq Llama 3.3).
* **The Agentic Loop (v3 — Multi-Agent):**
  `Ingest Context -> Synthesize Prompts -> Plan Fix -> Write Regression Test (red, shared) ->
  Dispatch to N Isolated Agents (own git worktree + own strategy each) ->
  [Apply Patch -> Execute Sandbox Tests -> Trim Error Trace -> Self-Correct Loop ->
  Critic/Reviewer Check] per agent, in parallel ->
  Arbitration Node (rank by critic score / retries / diff size, pick one winner) ->
  Human Approval Gate (optional, on flagged winner only) ->
  Git Commit (winning worktree only) -> Langfuse Telemetry (all attempts tagged) ->
  SWE-bench Scoring`.

## 4. What Changed vs v1 (Why Each Addition Matters)

1. **SWE-bench integration** — turns "it works on my dummy repo" into a comparable, credible
   number against the industry's actual leaderboard tools.
2. **Multi-file patch sets** — real bugs rarely live in one file; a signature change plus its
   call sites is the norm, not the exception.
3. **Unified-diff + fuzzy match + AST fallback** — literal search/replace breaks on whitespace
   drift; this raises the patch *apply* success rate independent of patch *correctness*.
4. **Regression-test generation (red→green)** — proves the bug is actually fixed, not just that
   pre-existing tests didn't break.
5. **Critic/Reviewer agent** — a second model with an adversarial prompt catches logic drift and
   scope creep that a passing test suite is blind to.
6. **Hardened sandbox** — explicit CPU/mem/time ceilings and no egress by default turn "isolated"
   into "actually safe to run autonomously."
7. **Live dashboard** — makes the "observability platform" claim true beyond just embedding
   Langfuse's own UI.
8. **Human approval gate** — the standard enterprise expectation before an autonomous agent is
   allowed to push a commit unsupervised, with a logged audit trail.
9. **Multi-agent dispatch + git worktree isolation + arbitration** — running 2–3 independent
   attempts in parallel (each in its own worktree, each with a different strategy) and picking
   the best one raises resolution rate the same way SWE-agent-style "multiple rollout"
   strategies do, without any risk of agents overwriting each other's work, because only the
   winning worktree's branch ever touches the shared branch.

## LAYA Decision Engine Integration

Every judgment point in the v3 agentic loop is decided by the **local LAYA** System-1
decision engine (`convaiinnovations/laya`) via typed `score`/`noul`/`choice` questions —
Gemini (planning) and Groq (patching) propose, LAYA decides:

- **Candidate scoring:** each Groq/Gemini attempt is scored with `fix_quality`
  (score), `matches_issue` (noul), `safe_to_apply` (noul).
- **Arbitration (fan-in):** best high score wins — `0.5*quality + 0.25*matches
  + 0.25*safety` — refined in a loop until the score plateaus, then ONE winner is
  merged. See `src/agents/arbitration.py` and `laya_pipeline.py`.
- **Critic gate before commit:** `secrets_or_danger` + `logic_drift` noul checks on
  the winner; flagged diffs pause at the human approval gate.
- **Final output check:** every committed/rendered file is verified with a noul
  question (P(correct) >= 60%) before a success claim.

Design intent: the model-split stays free-tier (Gemini 2.5 Flash + Groq Llama 3.3 70B),
but judgment moves from prompt-text heuristics to calibrated on-device probabilities.
