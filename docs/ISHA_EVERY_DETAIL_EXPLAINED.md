## 1. What is ISHA? (Agent Identity & Core Concept)

**ISHA (Iterative Software Harness & Arbitrator)** is an autonomous software engineering agent that solves real-world repository bugs without human intervention. 

Given an issue description (from GitHub or JIRA) and a target codebase, ISHA:
1. **Localizes** the bug down to the exact file, class, and root-cause symbol using BM25 and Tree-sitter AST structural parsing.
2. **Synthesizes** a standalone reproduction unit test that reproduces the bug (RED state).
3. **Generates** multiple competing candidate code fixes in parallel, isolated Git worktrees.
4. **Filters & Arbitrates** candidates using static AST compilation gates, unit tests, and empirical container invariants.
5. **Calibrates Approval** via the LAYA decision gate to prevent false-positive approvals.
6. **Exports** clean, unified git diff patches (`patch.diff`) verified under official SWE-bench Docker environments (GREEN state).

## 5. Official Docker Containers vs. Unverified Simulation Claims

### What is "Unverified Simulation"?
Many papers and repos claim high scores by cutting corners:
- **LLM-as-a-Judge**: Asking another LLM *"Does this patch look right?"* instead of running it.
- **Syntactic Counting**: Calling a task "passed" simply because `git apply` didn't error out.
- **Host Testing**: Running tests on a developer's laptop without exact legacy Python environments, missing dependencies, or database configurations.

### What is "Official Docker Container Execution"?
SWE-bench provides official Linux Docker images for every single repository and version:
1. Docker spins up an isolated sandbox with the exact historical repository environment (e.g. Django 1.10 on Python 3.6).
2. The agent's `patch.diff` is applied via git.
3. The official benchmark script (`eval.sh`) runs the real test suite:
   - **`FAIL_TO_PASS`**: The specific reproduction test that was failing on baseline **must turn green**.
   - **`PASS_TO_PASS`**: Hundreds of existing regression tests in the codebase **must continue to pass with zero regressions**.
4. The container produces a tamper-proof `report.json` containing the full pytest tracebacks.

**ISHA's scores originate 100% from real Docker container pytest execution.**

## 6. The 8 Empirical Negative Container Invariants (The Secret to 70%)

Why did ISHA jump from 36.7% (Session 1) to **70.0% (Session 4)**?  
Standard LLM coders break because they make subtle Python container mistakes. ISHA hardcodes **8 Empirical Negative Invariants**:

1. **Class Anchoring**:  
   *Rule*: Always insert methods and properties into the **exact target enclosing class**, never inside an earlier class, helper, or module level.  
   *Bug Prevented*: In `django-14915`, LLMs repeatedly pasted `__hash__` outside `ModelChoiceIteratorValue`. Anchoring fixed it.
2. **Guard Clause Completeness**:  
   *Rule*: Always check `if val is None:` before accessing attributes or calling `len(val)`.  
   *Bug Prevented*: Calling `len(None)` raises `TypeError`. Calling attributes on `None` raises `AttributeError`.
3. **Hashability Contracts**:  
   *Rule*: Never put mutable collections (`list`, `dict`, `set`) into sets, dictionary keys, or identity tuples without calling `make_hashable(...)` or converting to an immutable tuple.  
   *Bug Prevented*: In `django-14672`, proxy model comparisons raised `TypeError: unhashable type: 'list'`.
4. **Decorator Preservation**:  
   *Rule*: When wrapping callables or modifying decorators (`functools.partial`), always wrap with `@functools.wraps(...)` to preserve function introspection (`__name__`, `__doc__`, `__wrapped__`).  
   *Bug Prevented*: In `django-14787`, partial method wrappers lost attribute reflection.
5. **Execution Scope & Namespaces**:  
   *Rule*: In dynamic code execution (`exec`, `eval`), always provide an explicit global namespace with `{'__name__': '__main__'}` so top-level imports and closures resolve properly.
6. **Accessibility & Widget Contracts**:  
   *Rule*: In composite forms and widgets, `id_for_label` must return `''` or `None` if the widget has multiple sub-widgets without a single focus target.  
   *Bug Prevented*: In `django-15061`, composite widgets crashed form accessibility validators.
7. **Type & Return Invariants**:  
   *Rule*: Strictly preserve exact return types and falsy distinctions (`None` vs `''` vs `0` vs `False`). Never coerce `None` to `''` or drop empty strings.  
   *Bug Prevented*: In `django-15347`, message cookies dropped empty tags when `extra_tags=''` was coerced to `None`.
8. **Qualname Hierarchy**:  
   *Rule*: When serializing nested classes or methods, always use `__qualname__` to preserve the full enclosing scope hierarchy.  
   *Bug Prevented*: In `django-17087`, migrations failed to serialize nested method defaults.

## 10. Container File & Operating System Hygiene (POSIX LF vs. CRLF)

When running on Windows and shipping files into Docker Linux containers:
- **Windows CRLF (`\r\n`)**: Causes Linux bash scripts (`eval.sh`, `patch.diff`) to crash with `/bin/sh^M: bad interpreter` or patch rejection.
- **ISHA Invariant**: Every patch, script, and output file is strictly normalized to **POSIX LF (`\n`)** and **UTF-8 encoding**.
- **Local Isolation**: Sensitive planning files like `plan.md` are kept **strictly local and uncommitted** to prevent data leakage.

## 11. Why "Ponytail", "Taskmaster", and "Smoke 50" Were Removed

1. **Ponytail**: Was external prompt branding ("Ponytail Lazy Senior Mode"). While the *minimal diff discipline* was essential, the branding was unneeded. The actual resolution jump came from the **8 Negative Invariants**, not the name.
2. **Taskmaster**: Was a third-party project management CLI (`scripts/taskmaster.py`). It added no value to the core runner and was safely deleted to keep the repo clean.
3. **Smoke 50**: Was an early developmental test slice. Because Sessions 1–4 are official, full SWE-bench Lite benchmark runs with 70% and 55% verified rates, references to the developmental slice were removed to keep public documentation focused strictly on audited SWE-bench Lite milestones.
